本手册面向**使用者**，覆盖从安装启动到训练、合成、排障的完整流程。

## 1. 快速开始

### 1.1 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows（已适配）；Linux / macOS 可用 `scripts/start.sh` |
| Node.js | ≥ 18.17（推荐 20+） |
| Python | 3.9 ~ 3.12 —— **推荐直接用整合包自带的 `runtime/python.exe`**，里面已装好 torch |
| 显卡 | 建议 NVIDIA 8GB+ 显存（CPU 也能跑推理，但很慢；训练强烈建议 GPU） |
| GPT-SoVITS | 整合包放在项目同级目录，例如 `GPT-SoVITS-v2pro-20250604/` |

### 1.2 安装

```bash
npm run install:all
```

安装三处依赖：项目根目录（`concurrently`）、`app/`、`server/`。Python 侧依赖由本地服务自己处理，无需手动 `pip install`。

### 1.3 启动

**Windows 用户直接双击项目根目录的 `start.bat`。**

它会自动完成：检查 Node 版本 → 首次运行时安装依赖并做环境体检 → 启动三个进程 → 打开浏览器。

终端模式：

```bash
npm run dev        # 并行启动：本地模型服务 + 网关 + 前端
npm run dev:cloud  # 只用云端模型：只起网关 + 前端
npm run dev:sovits # 只起本地模型服务（想让它常驻时用）
```

启动后访问 **http://localhost:5173**。

### 1.4 验证安装

```bash
npm run sovits:check
```

退出码 `0` 表示就绪。它会明确告诉你：是否找到整合包、用的是哪个解释器、显卡型号、缺哪些依赖、以及下一步该做什么。

同一份信息在运行中也能查：`GET http://127.0.0.1:9881/health`。

### 1.5 启动后会发生什么

| 端口 | 进程 | 说明 |
| --- | --- | --- |
| 5173 | 前端（Vite） | 你看到的界面 |
| 8787 | Node 网关 | 代理本地服务、封装云端接口、托管构建产物 |
| 9881 | 本地模型服务 | Python 进程，持有模型 |

首次启动的等待时间：Python 侧 `import torch` 约 10~20 秒，模型预加载再花 30~90 秒。**这期间页面可正常打开**，侧栏会显示「正在连接」，服务就绪后自动变绿 —— 不需要刷新页面。

## 2. 核心概念

### 2.1 两条模型路线

| | **MiMo（云端）** | **GPT-SoVITS（本地）** |
| --- | --- | --- |
| 部署 | 无需本地算力，填 API Key 即用 | 需要本机 GPU 与整合包 |
| 音色来源 | 官方预置 9 个音色 | **没有内置音色**，必须自己导入参考音频 |
| 音色设计 | ✅ 用文字描述凭空造音色 | ❌ 不支持 |
| 声音克隆 | ✅ | ✅（5 秒音频即可） |
| 专属微调 | ❌ | ✅ |
| 语种 | 中文（含方言）、English | 中 / 英 / 日 / 韩 / 粤，且支持跨语言 |
| 数据流向 | 音频走云端接口 | **全程不出本机** |

**怎么选：**

- 想快速出声、不想装环境 → 路线 A（云端）
- 要克隆自己的声音、做日语/韩语、批量做有声书、或数据不能外传 → 路线 B（本地）

### 2.2 几个必须分清的概念

| 概念 | 是什么 | 关键点 |
| --- | --- | --- |
| **音色** | 一个人的声音特质 | 本地模型里，一个音色 = 一段参考音频 + 它的逐字文本 |
| **参考音频** | 让模型模仿的那段录音 | **3~10 秒**（官方推荐 5 秒）、单人、干净、无背景音 |
| **提示文本** | 参考音频里说了什么 | **必须逐字一致**，错一个字都会被学进去 |
| **参考音频语种** | 参考音频说的是哪种语言 | 与「合成文本的语种」是两回事，可以不同（跨语言合成） |
| **语料** | 训练用的成批素材 | 单人、安静、无背景音乐；1 分钟以上才能微调 |
| **训练清单（.list）** | 音频与文本的对应表 | 每行：`音频路径|说话人|语种|文本` |

### 2.3 界面里的术语提示

界面上**带灰色虚线下划线**的词都是专业术语：

- **桌面**：鼠标停在上面即显示解释（也可键盘 Tab 聚焦）
- **触屏 / 手机**：点一下弹出

解释分三部分：它是什么 → 它影响什么 → （部分术语）一个具体示例。

页面**右侧边缘**还有一条竖条，鼠标移到窗口最右侧会展开「**官方推荐流程**」—— 这是 GPT-SoVITS 开发者给出的标准步骤，边做边看，不必在文档和界面之间来回切。

## 4. 路线 A：MiMo 云端模型

### 4.1 配置密钥

1. 打开 **设置** 页
2. 在「MiMo API Key」处填入密钥（获取地址：https://platform.xiaomimimo.com/console/api-keys）
3. 密钥只存在**浏览器本地**，不会上传到本项目服务端

> 服务端也可以统一配置 `MIMO_API_KEY`（在 `server/.env` 中），配置后所有用户都不必再填。

### 4.2 通用语音合成

1. 进入「通用语音合成」
2. 在「预置音色」里选一个（如「冰糖」「茉莉」）
3. 输入文本
4. 可选：加风格标签、方言标签、语气指令
5. 点击合成

**MiMo 独有的控制方式**（这些对本地模型无效）：

| 功能 | 说明 |
| --- | --- |
| 风格标签 | 写在文本开头的情绪标记，如 `(开心)` |
| 方言标签 | `(粤语)` 等地域腔调 |
| 音频标签 | 插在句中的细粒度标记，控制停顿、语气 |
| 唱歌模式 | 把歌词以歌唱方式演绎 |
| 语气指令 | 一句话描述想要的演绎方式，不出现在语音里 |

### 4.3 音色设计

用一句描述生成全新音色，例如「沉稳的中年男声，语速偏慢，适合纪录片旁白」。这是**云端独有的能力**。

### 4.4 声音克隆

上传一段样本音频即可复刻音色。注意云端克隆时**音频会上传到厂商接口**；若素材敏感，请改走本地路线。

## 5. 路线 B：GPT-SoVITS 本地模型

### 5.1 第一步：导入音色（必做）

本地模型**没有内置音色**，第一步永远是导入参考音频。

1. 进入「音色库」→ 新建音色
2. 上传一段 **3~10 秒**的音频（推荐 5 秒左右的切分片段）
3. 填写**提示文本** —— 这段音频里逐字说了什么
4. 选择**参考音频语种**
5. 保存

**素材要求（决定成败）：**

- ✅ 单人说话，无背景音乐、无混响、无底噪
- ✅ 说话自然、音量稳定
- ❌ 不要带 BGM、不要有回声、不要多人对话

页面会回放这段音频，上传前先听一遍。

### 5.2 第二步：合成

**单条** —— 去「通用语音合成」，把模型切到 GPT-SoVITS，选中音色，输入文本合成。

**批量** —— 去「批量合成」：

1. 粘贴文本清单（每行一条），或导入 `txt` / `csv`
2. 选择音色
3. 可选：展开高级参数（切分方式、语速、temperature、复读惩罚、分桶、并行推理）
4. **先点「试听首条」**确认音色，再点「开始批量合成」
5. 完成后：逐条试听 / 下载 / 下载 ZIP（含 `audio/` + `manifest.json` + `index.csv`）

单条失败不影响其余条目，失败原因会留在结果列表里。

### 5.3 第三步（可选）：训练专属音色

零样本克隆够用就先不训练。想要更稳、更像，走训练流程（下一节）。

## 6. 参数配置详解

### 6.1 官方推荐流程（8 步）

来自 GPT-SoVITS 开发者，界面右侧可随时查看。摘要：

| 步骤 | 做什么 | 要点 |
| --- | --- | --- |
| 1 | 人声分离 | 素材有 BGM/噪声才需要；官方推荐 BS 模型；切分前删掉 other 背景音 |
| 2 | 语音切分 | 参数默认不动；切出来全偏长就把 300 改成 100~200；删掉 >15 秒的超长条 |
| 3 | 语音识别 | 中文/粤语用达摩 ASR，其它语种用 Faster Whisper |
| 4 | 标注校对 | 可跳过；但读音怪异时回来校对最有效 |
| 5 | 训练集格式化 | 只建议 V2 Pro / V2 Pro Plus |
| 6 | 微调训练 | 参数默认；**先 SoVITS 后 GPT**；DPO 不要开 |
| 7 | 推理选权重 | E = 轮数（选最大），S = 步数 |
| 8 | 合成设置 | 参考音频 5 秒左右；语种选参考音频的语种 |

### 6.2 训练页阶段开关

| 阶段 | 何时开 |
| --- | --- |
| 语料导入 | 始终 |
| **人声分离（UVR5）** | 素材带 BGM / 混响 / 延迟 |
| 语音降噪 | 有明显底噪（注意：该模型需联网下载，本地无缓存时可能失败） |
| 音频切分 | 长录音必须开；素材已是 5~15 秒小段可关 |
| 语音转文本 | 没有现成文本时开 |
| 生成训练清单 | 通常开 |
| 格式化训练集 | 始终开（含文本特征 / HuBERT / 说话人向量 / 语义 Token） |
| GPT（语义）训练 | 微调时开 |
| SoVITS（声学）训练 | 微调时开 |

### 6.3 切分参数（8 个）

默认值取自官方 WebUI，**绝大多数情况不用改**。

| 参数 | 默认 | 何时调 |
| --- | --- | --- |
| threshold 静音阈值 | -34 | 环境噪声大 → 调低（-40） |
| min_length 最小长度 | 4000 | 想保留短句 → 调小 |
| min_interval 最短间隔 | 300 | **切出来全部偏长 → 改成 100 或 200** |
| hop_size 音量曲线精度 | 10 | 一般不动（越小越慢） |
| max_sil_kept 静音保留 | 500 | 想更紧凑 → 调小 |
| max 归一化峰值 | 0.9 | 一般不动 |
| alpha 归一化混合 | 0.25 | 1=完全拉平，0=保持原音量 |
| n_parts 切片进程数 | 1 | 本机单显卡保持 1，避免抢资源 |

### 6.4 ASR 参数

| 项 | 建议 |
| --- | --- |
| 后端 | 中文/粤语 → FunASR（达摩）；其它语种 → Faster Whisper |
| 模型尺寸 | 越大越准但越慢；中文用 large，其它用 medium 或 large-v2/v3 |
| 精度 | Faster Whisper：显存紧张 float16/int8，求准 float32。**FunASR 官方注明该参数尚未接入，选了不生效** |
| 常驻模型 | 连续转写很多条时开，更快但持续占显存 |

### 6.5 训练超参

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| GPT epoch | 15 | 语料少（1~5 分钟）建议 15~30 |
| GPT batch | 6 | 显存不足降到 1~4 |
| SoVITS epoch | 8 | 不像本人时优先加这个 |
| SoVITS batch | 6 | 同上 |
| LoRA rank | 32 | 仅 v3/v4；语料少降到 8~16 |
| GPU 编号 | 0 | 多卡可填 `0-1` 分片 |

**官方建议：参数全部保持默认**（已按显存自动调整）。

### 6.6 合成参数

| 参数 | 作用 | 建议 |
| --- | --- | --- |
| 切分方式 | 长文本怎么断句 | 长文本 `cut5`，短句 `cut0` |
| 语速倍率 | 整体快慢 | 1.0 原速；改了音色会轻微变化 |
| temperature | 随机程度 | 要稳定 → 调低；要自然 → 略调高 |
| top_k / top_p | 采样收窄 | 通常二选一调整 |
| repetition penalty | 抑制复读 | 卡字/复读 → 调高（如 1.5） |
| 分桶 | 长度相近的批量推理 | 更快；语速 ≠ 1.0 时自动关闭 |
| 并行推理 | 同时处理多段 | 更快但更吃显存 |
| 变体推理 | 官方称提速约一倍 | 显卡弱无收益；V3/V4 无此选项 |

## 7. 常见任务操作流程

### 7.1 克隆自己的声音（最快路径）

1. 录一段 **5 秒**干净独白
2. 音色库 → 新建音色：上传 + 填逐字文本 + 选语种
3. 通用合成 → 模型切到 GPT-SoVITS → 选中音色 → 输入文本 → 合成

约 2 分钟完成。效果不满意再考虑训练。

### 7.2 训练专属音色（完整流程）

1. **准备素材**：单人、安静、1 分钟以上有效语音（5 分钟以上更好）
2. 训练页 → 填实验名 → 选语料目录
3. 按素材情况开阶段：带 BGM 开「人声分离」；长录音开「音频切分」；没文本开「语音转文本」
4. 点「**预检计划**」—— 先看看每一步会执行什么，参数错了当场就能发现
5. 点「开始训练」，观察阶段进度与日志
6. 训练完成后，权重写入 `GPT_weights_<版本>/` 与 `SoVITS_weights_<版本>/`
7. 合成时会自动优先使用最新训练的权重；想换成别的轮次，去「**设置 → 推理权重**」
   的下拉里选（文件名里 e = 轮数、s = 步数，一般选 e 最大的），点「加载所选权重」即可

> 想一次性测完零样本 + 训练 + 权重切换 + 批量的整条链路，按 [14.1](#141-gpt-sovits-全链路测试流) 的测试流走。

### 7.3 做有声书

1. 音色库准备好音色
2. 批量合成 → 粘贴/导入整章文本（每行一条）
3. 「试听首条」确认
4. 开始批量合成 → 下载 ZIP
5. ZIP 里的 `index.csv` 可用 Excel 打开，便于对号入座

**提示**：长句子用 `cut5` 切分更稳；遇到卡字把复读惩罚调到 1.4~1.6。

### 7.4 翻唱（歌声转换）

1. 进入「歌声转换」
2. 上传歌曲
3. 开「人声分离」（**带伴奏必须开**，否则伴奏会被算进人声）
4. 选目标音色
5. 长歌建议开「长音频自动切分」（避免 8GB 显存峰值溢出）
6. 开始转换

> 完整的测试流（前置权重、音色入位、分支场景与每步预期）见 [14.3](#143-歌声转换ddsp-svc全链路测试流)。

### 7.5 变声

1. 进入「语音变声」
2. 上传源音频（说话/配音干声，建议 ≤5 分钟）
3. 选目标音色
4. 按需设 F0 方法与变调（半音）
5. 开始 → 完成后可 A/B 对比原声与变声

> 完整的测试流（前置权重、音色获取、工坊融合 / LoRA、分支场景）见 [14.2](#142-语音变声rvc全链路测试流)。

### 7.6 批量转写素材（ASR）

1. 进入「语音转文本」
2. 选场景预设 → 后端 / 模型尺寸 / 语种
3. 上传音频或填语料目录
4. 设置数据集名称
5. 开始转写 → 产出 `.list` 清单，可直接用于训练

### 7.7 校正 ASR 的错字

转写完成后，若任务产出了清单，训练页会出现「**标注校对**」面板：

- 左边播音频，右边改文本
- 可标记「丢弃这条」（音频有问题时）
- 保存后点「用这份清单训练」—— 会自动填入清单路径**并关闭语音转文本**，避免下一轮又被 ASR 覆盖

> 官方认为这一步非常耗时、收益有限，**可以跳过**。但如果合成结果里某些字读音怪异，回来校对对应条目是最有效的排查手段。

## 8. 进阶功能

### 8.1 UVR5 人声分离

在训练页开启，模型从整合包扫描（只列真实存在的）：

| 模型 | 用途 |
| --- | --- |
| HP2_all_vocals | 保留人声（无和声）—— 默认 |
| HP5_only_main_vocal | 仅保留主人声（有和声时） |
| VR-DeEchoNormal / Aggressive | 去延迟 |
| VR-DeEchoDeReverb | 去延迟 + 去混响（耗时约 2 倍） |
| onnx_dereverb_By_FoxJoy | MDX-Net 去混响（双通道有效，不能去单通道） |
| BS-RoFormer | **官方首选**。训练页的模型列表因缺 `.yaml` 把它标为不可用（需补齐配置）；**歌声转换页的分离引擎不受此限** —— 缺 `.yaml` 时自动使用内置默认配置，可直接跑 |

输出人声与伴奏两份，**只保留人声进入后续流程**。

### 8.2 预训练权重自定义

设置里留空即用整合包自带权重。想接着自己训过的权重继续练，或换社区权重时，在训练页「预训练权重」处填绝对路径。路径不存在会在**预检阶段**就报错，不会拖到训练中途。

### 8.3 权重与版本

- 版本：**官方只建议 V2 Pro / V2 Pro Plus**（界面上已标注「官方推荐」）
- 权重文件名：`E` = 训练轮数，`S` = 步数。例 `my-voice_e16_s2160.pth` → 第 16 轮第 2160 步
- 官方建议选 **E 最大**的那个

### 8.4 音色工坊（变声页）

两条缓解「换音色就要重训」的路径：

- **音色融合**：把两个权重按比例混合，零训练，几分钟试出方向
- **LoRA 微调**：只训约 4% 参数，产物几 MB，可热切换

## 9. 注意事项

### 9.1 素材质量决定上限

模型只能逼近素材的质量。以下会直接毁掉结果：

- 带背景音乐 → 必须先做人声分离
- 混响/回声 → 去混响
- 底噪 → 降噪
- 多人对话 → 分开处理
- 参考音频 >10 秒或 <3 秒 → 裁剪到 5 秒左右

### 9.2 提示文本必须逐字一致

错一个字都会被学进模型，表现为**某些字读音怪异**，而且事后极难定位是转写错了还是模型学歪了。

### 9.3 语种的两个概念

- **参考音频语种** = 参考音频说的是什么语言
- **合成语种** = 你要合成的文本是什么语言

两者不同 = 跨语言合成（如中文音色读日语）。官方特别强调这一点容易搞混。

### 9.4 显存管理

- 训练会**独占显卡**，期间不要同时批量合成
- 显存不足时优先降 batch、再关并行推理、最后开梯度检查点
- 8GB 显卡：处理长歌要开「长音频自动切分」
- 半精度（float16）在 8GB 卡上基本必须开

### 9.5 数据安全

- 本地模型路线：**数据不出本机**
- 云端模型（MiMo）：音频会走厂商接口，敏感素材请走本地
- 密钥只存浏览器本地

### 9.6 合规

克隆他人声音需获得明确授权；禁止用于伪造身份、诈骗等违法用途。

## 10. 故障排查

### 10.1 启动类

| 现象 | 排查 |
| --- | --- |
| 双击 `start.bat` 窗口一闪就没 | 前置检查失败。脚本出错时会暂停等待按键；若窗口直接消失，多半是文件被改成 UTF-8（**必须是 ANSI/GBK**）。在终端里执行 `start.bat` 可看到完整报错 |
| 提示端口 8787 / 5173 被占用 | 上次的服务没关干净。脚本会打印占用进程 PID，`taskkill /F /PID <PID>` |
| 侧栏一直「正在连接」超过 90 秒 | 本地服务真没起来，看终端 `[sovits]` 段的输出；或跑 `npm run sovits:check` |
| `npm run dev` 报 `concurrently 不是内部或外部命令` | 根依赖没装，执行 `npm install` |

### 10.2 合成类

| 现象 | 原因与处理 |
| --- | --- |
| **「不支持合成语种 undefined」** | 音色的「参考音频语种」存成了脏数据。服务启动时会自动纠正为 `zh`；若仍出现，到音色库把该音色语种重选一次 |
| **「未知模型版本 v2proplus」** | 已修复（前后端双向归一化）。若复现请贴版本号 |
| 合成失败弹窗反复出现 | 已修复（依赖改为具体 error）。若复现请截图 |
| 页面一片全白 | 现在会显示「页面渲染出错」卡片，含错误信息与调用栈。按卡片提示操作，或点「重置本地配置后重载」 |
| 某些字读音怪异 | 提示文本/标注有错字。到标注校对里改对应条目 |
| 出现卡字、复读 | 复读惩罚调到 1.4~1.6 |
| 声音不像本人 | 换更干净的参考音频；或增加 SoVITS 训练轮数 |
| 训练期间合成被拒绝 | 正常：训练独占显卡。等训练结束或先取消 |

### 10.3 训练类

| 现象 | 处理 |
| --- | --- |
| 预检报「缺少 UVR5 模型」 | 确认整合包 `tools/uvr5/uvr5_weights` 里有 `.pth / .ckpt / onnx` 权重 |
| BS 模型选不了 | 缺同名 `.yaml`，先用 HP2 / HP5 |
| 切分结果全部偏长 | min_interval 从 300 改成 100 或 200 |
| 降噪阶段失败 | `tools/denoise-model/` 是空目录，模型需联网下载。改用 UVR5 的 DeEcho / ONNX 去混响 |
| 显存不足（OOM） | 降 batch → 关并行 → 开梯度检查点 → 关闭 GPT 或 SoVITS 只训一个 |
| 训练中途看不到进度 | 切换页面不会丢（会自动恢复轮询）。若仍卡住，查任务日志 |

### 10.4 快速自检清单

```bash
npm run typecheck      # 类型检查
npm run sovits:check   # 环境体检（退出码 0 = 就绪）
npm run build          # 构建
```

浏览器打开 http://localhost:5173，控制台应无报错。

## 11. 最佳实践

### 11.1 素材

- 录音环境：安静小房间，远离墙面（减少混响）
- 用耳机麦或指向性麦克风
- 一次录 5~10 分钟，再切分成 5~15 秒小段
- 保持音量稳定，避免忽大忽小

### 11.2 参考音频

- **5 秒左右**最佳
- 选情绪平稳、发音清晰的句子
- 避免「嗯」「啊」等语气词开头

### 11.3 训练

- 先跑「预检计划」再提交 —— 参数错误当场可见
- 参数保持默认，不要随手调
- 微调前先确认素材已处理干净（分离/切分/转写）
- 训练顺序按官方建议：**先 SoVITS 后 GPT**
- DPO 不要开

### 11.4 合成

- 批量合成前一定先「试听首条」
- 长文本用 `cut5`；短句用 `cut0` 更连贯
- 一次提交几百条，比反复点击高效得多
- 结果用 ZIP 下载，保留 `index.csv` 便于对号入座

### 11.5 迭代

- 先零样本克隆试效果，不够再训练
- 训练后 A/B 对比，确认是否真的变好
- 每次只改一个变量，便于定位影响

## 14. 全链路测试流

> 供验收与回归测试用。每个板块一条**完整数据链**：先走主链路（每步附「预期」，即为通过标准），
> 再逐项过「分支场景」表 —— 表里的每一行都是用户真实会踩到的路径。
> 快速上手版操作说明在[第 7 节](#7-常见任务操作流程)，这里不重复截图级细节，只补判定标准。

### 14.1 GPT-SoVITS 全链路测试流

**数据链总览**：

```
环境体检 → 音色库导入 → 零样本合成（含跨语言）→ 语料预处理（分离/切分/识别）
→ 标注校对 → 格式化 → SoVITS 训练 → GPT 训练 → 权重切换 → 批量合成 → 历史
```

**前置条件**：

- `npm run sovits:check` 退出码 0；浏览器打开 `http://localhost:5173` 三端口就绪
- 素材 A：一段 **5 秒**干净独白（测零样本克隆）
- 素材 B：**5 分钟以上**单人长录音，最好带轻微 BGM（才能真实验证人声分离与切分）
- 素材 C：任一训练产物出现后自动生成，无需准备

**主链路**：

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 看侧栏连接状态 | 显示「已就绪」；设置页 GPT-SoVITS 卡片有显卡型号、Python/torch 版本、音色库数量 |
| 2 | 音色库 → 新建音色：上传素材 A + 逐字提示文本 + 语种 zh → 保存 | 列表出现新音色，能回放，无 ⚠️ warnings |
| 3 | 通用合成 → 切 GPT-SoVITS → 选该音色 → 输入中文 → 合成 | 出声且音色接近素材 A；结果可试听 |
| 4 | 同一音色把「合成文本语种」切 `en`，输入英文再合成 | 出现**跨语言提示卡**（参考音频语种 ≠ 合成文本语种），仍能出声 |
| 5 | 训练页 → 实验名 `e2e-test` → 选素材 B 目录 → 开：人声分离（HP2）+ 音频切分 + 语音转文本 + 格式化 + SoVITS + GPT → 点「预检计划」 | 阶段数与勾选一致，命令预览无报错 |
| 6 | 开始训练，观察进度卡 | 流水线顺序为 `… 语义 Token → SoVITS 训练 → GPT 训练`（官方顺序） |
| 7 | 等切分阶段完成 | 进度卡出现**切分结果面板**：明细按时长从大到小，>15 秒的条目琥珀色高亮；数字与日志「切分产出 N 段」一致 |
| 8 | 等训练全部完成 | 出现绿色「训练产物已就绪」卡片，含 `_eN_sM` 命名的权重路径 |
| 9 | 在训练页「标注校对」面板改一条转写文本 → 保存 → 点「用这份清单训练」 | 保存成功；表单的清单路径被回填且「语音转文本」自动关闭 |
| 10 | 设置 → 推理权重：看两个下拉 | 训练产物按时间新→旧排列（e 最大的在最前），另有「官方预训练底模」选项 |
| 11 | 选一对训练产物 → 点「加载所选权重」 | toast「权重已加载」；「当前生效」变为所选路径 |
| 12 | 回通用合成，用同一段文本再合成一次 | 用的是新音色（与第 3 步对比有明显差异） |
| 13 | 批量合成 → 粘贴 3 行文本 → 选音色 → 试听首条 → 开始 → 下载 ZIP | 逐条出结果；ZIP 含 `audio/`、`manifest.json`、`index.csv`（Excel 可开） |
| 14 | 历史记录页 | 第 3/4/12 步的结果都在，可回听、可删除 |

**分支场景**：

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 切分开了但没开 ASR（语料也无 .lab） | 关「语音转文本」、开「音频切分」、预检 | 预检即报「开启切分后必须开启语音转文本」，不进入训练 |
| 语料带同名 .lab 文本 | 开切分、关 ASR、预检 | 放行：清单由 .lab 生成（「生成训练清单」阶段出现） |
| FunASR + 英语语料 | 语种选 `en`、后端 FunASR、预检 | 报「FunASR 只支持中文与粤语」，hint 建议换 faster-whisper |
| 语料目录填错 | 填一个不存在的路径 | 报「语料目录不存在」，hint 说明上传后要用返回的目录 |
| 只勾 GPT 不勾 SoVITS | 关 s2、开 s1、开始 | 进度视图只有 GPT 训练阶段，且它在 SoVITS 缺席时正常执行 |
| 关「格式化」但数据集文件缺失 | run_format 关闭后预检 | 报「缺少必需的数据集文件」，不会拖到训练中途才炸 |
| 显存不足 | batch 拉满再训 | 训练失败，日志末尾有报错，hint 提示常见原因（显存不足、语料过少） |
| 从未训练过时看权重下拉 | 打开设置页 | 只有「官方预训练底模」选项，合成走零样本，不报错 |
| 音色库新建校验 | 不选音频 / 不填文本 / 不填名称分别提交 | 分别被拦截：「请选择音频文件…」「未识别到文本」「请填写音色名称」 |

### 14.2 语音变声（RVC）全链路测试流

**数据链总览**：

```
引擎权重就位 → 音色进库（导入 .pth / LoRA 训练 / 融合，三来源）
→ 变声推理 → A/B 对比 → 新音色再进库（闭环）
```

**前置条件**：

- 必需权重已就位（缺失时设置页「本地服务尚未就绪」会逐条列出文件名与应放路径）：
  - `vendor/rvc/assets/hubert/hubert_base.pt`（约 378MB）
  - `vendor/rvc/assets/rmvpe/rmvpe.pt`（约 58MB）
  - 下载地址与备用镜像见 `trainer/app/weights.py` 的权重清单（HuggingFace / hf-mirror）
- **至少一个现成音色 .pth**（社区分享或官方演示模型）。注意：**首个音色只能靠导入** ——
  音色工坊的 LoRA 训练要选已有模型当底模，融合也要至少两个现成模型
- 源音频两段：30~60 秒说话干声（主链路用）；一段性别相反的说话声（测变调）

**主链路**：

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 打开「语音变声」页 | 顶部引擎徽章显示「未加载音色（选择模型后自动加载）」，不是报错卡 |
| 2 | 音色模型库 → 导入 .pth（可选再点「配套 .index」导入索引） | 卡片出现，显示采样率 / 版本 / 带 F0 / 体积 / 是否含索引 |
| 3 | 开始变声：上传说话干声 → 选目标音色 → F0 `rmvpe`、变调 0、检索特征占比 30%、清辅音保护 0.33 → 开始 | 任务面板出进度；完成后出现「原声 / 变声后」A·B 对比播放器 |
| 4 | 工坊 → 音色融合：勾 2 个模型 → 拖比例 → 填名称 → 融合生成 | 提示「已生成新音色」；模型库出现新卡片 |
| 5 | 用融合音色再变声一次 | 正常出声（音色介于两个父模型之间，人工判断） |
| 6 | 工坊 → LoRA 微调：选底模 + 填本机语料目录（10~30 分钟干净干声）→ 轮数 20、rank 8 → 开始 | 训练任务走完；模型库自动出现成品音色（底模折入适配器的 .pth），并构建检索索引 |
| 7 | 热加载 LoRA 产物并变声 | 正常出声；顶部徽章变为「已加载 …Hz · cuda」 |
| 8 | 变调分支：男→女 +12、女→男 −12、同性 0 各跑一次 | 音高随变调整体移动；0 时音高不漂移 |

**分支场景**：

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 不选音频或模型就点开始 | 直接点「开始变声」 | 按钮禁用；绕过时提示「请先选择音频与目标音色」 |
| 模型没有配套 .index，检索占比 > 0 | 选无索引模型，检索 30% | 不报错：检索自动跳过，仅音色相似度略降 |
| 检索特征占比拉到 0 | index_rate = 0 变声 | 完全不用索引，正常出声 |
| 删除音色 | 点模型卡「删除」 | 从库中消失，下拉不再出现 |
| 必需权重缺失 | 移走 rmvpe.pt 后刷新设置页 | blockers 列出「缺少 RVC …应放在 …」；变声推理报错并指明缺的文件 |
| F0 方法换 `pm` / `harvest` / `crepe` | 逐个切换变声 | 都能出声（pm/CPU 也能跑；crepe 需要 torchcrepe，缺依赖时按报错提示处理） |

### 14.3 歌声转换（DDSP-SVC）全链路测试流

**数据链总览**：

```
引擎权重就位 → .pt 音色入位 → 只做分离（旁路，产物进缓存）
→ 翻唱向导：分离（命中缓存则跳过）→ 歌声转换 → 混音 → 三件套试听
```

**前置条件**：

- 必需权重已就位，放在 `models/pretrained/ddsp/`（缺失时设置页 blockers 逐条提示）：
  - `ddsp/contentvec/pytorch_model.bin`（约 300MB）
  - `ddsp/nsf_hifigan/model`（约 60MB，zip 需解压，同目录要有 `config.json`）
  - `ddsp/rmvpe/model.pt`（约 58MB，zip 需解压）
- **至少一个 SVC 音色**：`模型名.pt + config.yaml` 放进 `.data/svc/models/<名字>/`
  （或 `models/checkpoints/ddsp/`）。本页没有上传入口；
  也可调 API `POST /v1/svc/models/upload` 导入（.pt 与 config.yaml 一起传）
- 测试歌曲：一首 3~4 分钟**带伴奏**的歌；另备一段纯人声干声

**主链路**：

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 打开「歌声转换」页 | 顶部徽章「可用音色 N」；目标音色出现在下拉且不带「缺 config.yaml」 |
| 2 | 只做分离：上传歌曲 → 快速 HP2 → 开始分离 | 人声 / 伴奏可切换试听；提示「本次耗时 Xs」 |
| 3 | 同一首歌再分离一次 | 提示「命中缓存」—— 分离产物按内容指纹复用 |
| 4 | 翻唱向导：上传同一首歌 → 分离「快速 HP2」、二级处理「无」、长音频自动切分开 → 目标音色 → 音质「标准」→ F0「跟随模型」→ 转调 0 → 混音默认（人声 0dB / 伴奏 −3dB / 延迟 0ms）→ 一键开始 | 任务进度走完；产物区出现「新人声 / 伴奏 / 混音」标签，可切换试听 |
| 5 | 换一个音色重跑同一首歌 | 任务日志显示分离命中缓存（秒级跳过），只有转换与混音重跑 |
| 6 | 混音调优：伴奏 −3→0dB、人声 0→−2dB 重跑 | 混音比例变化；分离仍命中缓存 |
| 7 | 转调分支：+12（男歌女唱）、−12（女歌男唱） | 音高整体移动且不破音；换算自转调半音数 |

**分支场景**：

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 输入已是干声 | 分离预设选「跳过（输入已是干声）」 | 直接转换；产物只有转换结果，**没有**「伴奏」「混音」标签，不报错 |
| 音色缺 config.yaml | 目录里只放 .pt 不放 config.yaml | 下拉中该项禁用并标注「缺 config.yaml」，选不了 |
| 长歌 + 8GB 显存 | 4 分钟以上的歌，开「长音频自动切分」 | 按静音分段推理，不溢出；关掉则可能显存峰值溢出报错 |
| 音质四档 | 快速 → 标准 → 高质 → 纯 DDSP 各跑一段 | 速度递减（快速约 1 分钟/4 分钟歌）；「纯 DDSP」音色偏电子 |
| F0 方法 | rmvpe / parselmouth / dio / harvest / crepe / fcpe 逐个试 | 均按 catalog 提示工作（crepe、fcpe 需额外依赖，缺了会明确报错） |
| 高保真分离（BS-RoFormer） | 分离预设选「高保真 BS-RoFormer」 | 本机缺同名 .yaml 时**仍可跑**（自动用内置默认配置）；耗时与显存明显更高 |
| 二级处理 | 去回声（温和/强力）、去混响 分别试 | 人声更干净；去混响耗时约翻倍 |

**通过标准**：三个主链路表格中每一步的「预期」全部成立；分支场景表没有出现「预期」之外的报错。
任何一步不符，先查浏览器控制台与本地服务日志（`logs/`），再对照[第 10 节](#10-故障排查)。

## 15. 网易模块（Confucius4-TTS / R2T2）

> 独立的第二个 Python 运行时（`netease/`，端口 9882），**opt-in**：不随 `start.bat` /
> `npm run dev` 启动，装好才用、没装界面显示「待补齐」而不报错。
> 架构与对比结论见 `docs/NETEASE-INTEGRATION.md`。

### 15.1 它解决什么

| 场景 | 用谁 |
| --- | --- |
| 中文日常合成、批量出音频 | GPT-SoVITS（更快，现状不变） |
| 不想部署任何东西 | MiMo 云端（现状不变） |
| **免逐字转写**的克隆、德法西泰俄等 14 语种、跨语种无口音、情感迁移 | 网易 · 零样本合成 |
| 实时听写、打字幕（append-only 真流式，不出回改字） | 网易 · 流式转写 |

### 15.2 启用步骤（一次性）

1. 按 `netease/README.md` 建 venv（Python 3.10~3.12）→ 装 `requirements.txt` → 装 CUDA 版 torch；
2. 下载权重：`npm run netease:weights`（TTS 侧约 5.4 GB；R2T2 加 `--include-r2t2`；
   国内环境可用 `npm run netease:weights -- --proxy http://127.0.0.1:7890` 走本机代理）；
3. `npm run netease:check` 逐项体检，阻断项清零后 `npm run dev:netease` 启动
   （Windows 上没有 vLLM，R2T2 用不了，体检加 `--allow-missing-asr` 只校验 TTS）；
4. 浏览器侧栏「网易模块」两张状态卡由「未启动 / 待补齐」变「已就绪」。

### 15.3 全链路测试流

**前置条件**：`npm run netease:check` 退出码 0；netease 服务在跑（侧栏网易两卡绿色）。

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 侧栏看网易两卡 | 「已就绪」；服务没起时是「未启动」（文案含启动命令，不是故障语气） |
| 2 | 网易 · 零样本合成 → 引擎卡点「预热引擎」 | toast「TTS 引擎已就绪」；首次需加载模型（几十秒，权重未下载时明确报缺什么） |
| 3 | 上传一段 ≥3 秒音频（不填任何转写文本）→ 选语种 zh → 合成 | 出声且音色接近参考音频；结果卡可播放、可下载 WAV |
| 4 | 从音色库选择一条已有音色 → 合成 | 直接复用其参考音频成功；页面注明「逐字转写文本不参与合成」 |
| 5 | 合成语种切 `en`（或德/法/泰）输入对应语言文本再合成 | 出声且无明显本族口音（跨语种是本模块卖点） |
| 6 | 网易 · 流式转写 → 上传音频 → 模式切「流式转写」→ 开始 | 文本逐块增长且**已输出部分不变**（append-only）；结束出定稿，可复制/下载 TXT |
| 7 | 模式切回「快速转写」→ 勾「输出时间戳」→ 开始 | 一次性返回全文 + 逐条时间戳 |
| 8 | 在 TTS 页预热后去 ASR 页预热（8 GB 卡） | 后者 toast「已卸载另一引擎为 ASR 让位」；两引擎互斥、自动让位，不 OOM |

**分支场景**：

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 权重没下载就预热 | 引擎卡「预热引擎」 | 报 `DEP_MISSING` / `MODEL_LOAD_FAILED`，hint 指向 netease/README.md，不静默卡死 |
| 不上传参考音频直接合成 | 「开始合成」按钮置灰 | 无法点击；绕过 UI 直接调 API 则报 `REF_AUDIO_REQUIRED` 并带 hint |
| GPT-SoVITS 正占显存时预热网易 | sovits 服务在跑时预热 | 报 `VRAM_INSUFFICIENT`（跨进程占用看不见），hint 提示先关 sovits |
| netease 服务未启动 | 直接打开网易页面 | 页面可用，状态卡显示「未启动（可选模块）」+ 启动命令；合成/转写报 NETEASE_UNREACHABLE |

### 15.4 注意事项

- 两个网易引擎**共用一张卡**：同一时刻只驻留一个，预热另一个会自动卸载当前引擎（页面有说明）；
- R2T2 权重是**网易自有许可**（代码才是 Apache-2.0），商用前需单独确认；TTS 代码与权重均为 Apache-2.0；
- 网易模块的产物在 `netease/.data/`（TTS 音频、上传的参考音频），排障时可查。

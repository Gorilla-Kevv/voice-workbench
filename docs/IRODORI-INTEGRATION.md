# Irodori-TTS 集成说明（日语合成 + 音色固化）

> 面向**使用者**的一页说明：页面上有什么、每一步在干什么、出问题看哪里。
> 技术方案与阶段拆解见 `docs/IRODORI-INTEGRATION-PLAN.md`，实测数据见 `docs/IRODORI-TTS-EVALUATION.md`。

**定位**：Irodori-TTS 是本项目里的第四个 Python 运行时（:9884，日语特化）。
它不替代网易 / IndexTTS —— 那两条是中文/多语种主力；这里解决的是三件它们做不到的事：

1. **日语**本身（假名、长短音、句尾语调都按日语训练的）；
2. **emoji 风格标记**（😊 / 😡 / 🥳 …写在文本里，模型就按那个情绪读）；
3. **音色固化**（Speaker Inversion）：把某个人的音色训成一个 49KB 的 embedding，
   之后合成**不用再给参考音频**。

---

## 1. 先让它跑起来

它是**按需启动**的模块（默认不随主程序拉起，显存留给主力模型）：

- 界面：设置 → 本地服务 → **Irodori-TTS** 开关（网关托管，关掉会卸模型并归还显存）；
- 命令：`npm run dev:irodori`；
- 体检：`npm run irodori:check`（缺什么会直接说）。

首次使用还要下权重（约 4GB）：

```bash
npm run irodori:weights                 # 推理档（合成必需）
npm run irodori:weights -- --training   # 训练档 bf16 基座（音色固化必需，约 2.9GB）
```

## 2. 页面一：Irodori · 日语合成

侧栏 **「Irodori · 日语特化 → 日语合成」**。

| 区块 | 说明 |
| --- | --- |
| 资源预估 | 跑之前把「要多少 / 还剩多少」摆出来。不够时给的是能点的动作（释放显存 / 降步数 / 手动指定 batch），不是一句「资源不足」 |
| 引擎状态 | 权重是否齐、模型是否常驻；可手动「预热」（首次约 20~30s）与「释放显存」 |
| 日语文本与风格 | 文本 + **emoji 风格标记**（点一下追加到文本末尾）+ caption 预设 |
| 采样参数 | 步数（档位来自服务端）、采样调度、时长系数、换 seed |
| 参考音色 | **三选一**：固化音色（`speaker_id`）/ 音色库音色 / 本地路径 |
| 结果 | 多条结果堆叠，最新一条展开，每条独立播放 / 下载 / 删除 |

几点刻意的设计：

- **参数不抄在前端**：步数档、emoji 表、caption 预设、时长范围全部来自 `/v1/catalog`，
  服务端换档，界面跟着变。
- **长文本交给服务端分段**：它有 180s 墙钟护栏与「段间自动降步」，撞上长尾会返回
  带建议步数的 504，界面上给一个「重试（降步）」按钮 —— 重试用的是**失败那一次的请求**
  加服务端建议的步数，不会偷偷换成你后来改过的参数。
- **护栏介入过会说出来**：结果卡里会写「从第 N 段起自动降步并换了 seed」，
  免得你以为自己设的步数生效了。
- **固化音色优先**：选了 `speaker_id` 就不用再给参考音频（两者互斥）。

## 3. 页面二：Irodori · 音色固化训练

侧栏 **「Irodori · 日语特化 → 音色固化训练」**，三步向导（前置关系是真的，所以不平铺）：

### 第一步 · 语料

三个来源**互斥**（SI 训练必须是同一个说话人，给多个服务端会报错）：

| 来源 | 适合什么 |
| --- | --- |
| 已整备数据集 | 之前整备过，直接训 |
| 上传语料 | 一批日语短句 wav + 同名 `.txt` 转写（也可整包 `.zip`，或用 `metadata.jsonl`） |
| 音色库长参考 | 音色库里已经登记的「日语长参考」片段 |

选好来源后**自动体检一次**（不跑任何编码）：告诉你能用几条、合计多长、缺转写的有哪些、
训练基座在不在。**数据问题在这一步就暴露**，不用等排完队才发现。

> 官方建议 ≥10 条短句。条数太少会把韵律一起固化进去（合成出来的东西会「学走」那几句的调子）。

### 第二步 · 整备（S1+S2）

点「开始整备」入队：把音频编成 latent 并写 `manifest.jsonl`。
它会**先卸载常驻的推理模型**（显存全给整备），跑完会主动把显存还回来。

### 第三步 · SI 训练（S3）

选步数与 batch，点「开始训练」：

- **自动 batch**（默认）：开训前真的跑两步量一次显存，再按空闲显存的比例挑一个 batch；
  **手动指定**则跳过探测（显存紧张时降到 1~2 最稳）。
- 任务面板实时显示四个阶段（`plan → train → save → register`）、百分比、**预计还需多久**，
  以及服务端日志的尾部；随时可**取消**（取消会连进程树一起收掉，不留占显存的孤儿）。
- 训练期间**合成请求一律 409**：8GB 卡上「边训边合成」只会两边都崩 —— 训练独占显卡。

训完会给你一个 `speaker_id`，并提示「去合成页试试」。给了 `voice_id` 的话，
产物会顺带登记进音色库的 `speaker_embeds` 字段。

## 4. 产物落在哪

| 东西 | 位置 |
| --- | --- |
| 训练中间产物 | `irodori/.data/trainings/<dataset>-<job>/`（含周期 checkpoint） |
| 固化音色（对外契约） | `irodori/.data/speakers/<speaker_id>.speaker.safetensors` |
| 数据集与 latent | `irodori/.data/datasets/<dataset_id>/`（`manifest.jsonl` + `latents/`） |
| 任务记录 | `irodori/.data/jobs/<job_id>.json`（重启后未完成的任务会转成「已取消」） |

`/v1/speakers` 列出来的就是可以直接用于合成的固化音色。

## 5. 出问题看哪里

界面上的错误条会带**服务端给的 hint**（不是「请求失败」四个字），常见几类：

| 现象 | 原因与动作 |
| --- | --- |
| `IRODORI_UNREACHABLE` | 服务没起：设置页打开开关，或 `npm run dev:irodori` |
| 显存不足（训练） | 桌面占太多：关掉浏览器硬件加速 / 模拟器；或把 batch 改成手动 1~2 |
| `TRAIN_NO_DATA` / 数据为空 | 语料缺转写，或 latent 被清理了 —— 重新整备 |
| 训练中途 OOM | 降 batch；8GB 卡上 batch 8 已接近上限 |
| 联网失败（加载分词器） | SI 路径的分词器从 HF 缓存读；确认 `HF_HOME` 指向的缓存里有 `sbintuitions/modernbert-ja-310m` |
| 训练跑完但没有产物 | 服务端会判 `TRAIN_NO_ARTIFACT`（退出码 0 ≠ 真的训出来了），看任务日志尾部 |

侧栏状态卡与设置页用的是**同一套探活**（不会出现「侧栏说就绪、设置页说未启动」的两套事实源）。

## 6. 已知边界

- **音色质量要耳朵验收**：目前的验证只证明链路通（loss 从 0.91 降到 0.70、能出音），
  像不像本人需要你听过再判断。
- **`seconds_per_step` 估时偏保守**：早期 batch 8 实测 2.2s/步，30-6 小样本 batch 2 实测约 0.5s/步。
  任务里的「预计还需」是**本次实测**外推的，比开跑前的估算准。
- **Irodori 还没接进资源仲裁器**：资源卡上的「把资源集中给这一个模型」按钮对它无效，
  显存不够时只能手动关掉别的程序。
- 训练与推理**互斥**且训练独占：想一边训一边试听，只能等它跑完。

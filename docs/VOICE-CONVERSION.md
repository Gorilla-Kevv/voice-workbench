# 语音变声（RVC）

> 上游：[RVC-Project/Retrieval-based-Voice-Conversion-WebUI](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI)
> （`vendor/rvc`，20240604 分支，锁 commit）。本服务的直连层在 `trainer/app/vc/`。

## 定位

把一段**说话 / 配音 / 朗读的干声**换成另一个音色：保留内容、语气与节奏，
替换音色本身。音高只做整体变调（transpose），不逐帧建模音高曲线 ——
这是它适合说话、而不适合翻唱的原因（歌声请用「歌声转换」板块）。

## 能做什么

| 能力 | 说明 |
| --- | --- |
| 音色库 | `.pth` 权重 + 可选 `.index` 检索索引，放在 `trainer/.data/vc/models/` 或界面导入 |
| 变声推理 | 变调（±12 半音）、F0 提取方法、检索占比、清辅音保护等参数全量透传 |
| 音色融合 | 多个已有模型按权重插值出**零训练**的新音色，秒级 |
| LoRA 微调 | 底模共享 + 低秩适配器（约 4% 参数），每个新音色只训一个几 MB 的适配器 |
| 全量微调 | 复用官方 `train.py`，用于训练底模本身 |
| 检索索引 | 训练后自动用 faiss 建索引，提升音色相似度 |

## 缓解「换一个音色就要重训一个模型」

RVC 的原生用法是每个音色全量微调出一个完整模型。本服务提供两条缓解路径：

1. **音色融合（零训练）**：同一架构的 2~N 个模型做权重插值。适合
   「在两个已有音色之间造一个中间音色」的场景，界面拖滑杆即可；
2. **底模 + LoRA（轻训练）**：底模只训一次（或直接用官方预训练权重），
   之后每个音色只训一个 rank 8~32 的低秩适配器（约 1.5M 参数、几 MB），
   可热切换、可叠加。训练用非对抗式损失（mel 重建 + KL），
   比全量 GAN 训练快数倍，代价是音色上限略低 —— 想要极致音色再用全量微调。

## 使用流程

1. 「语音变声」页 → 模型库导入 `.pth`（选中即热加载，无需重启）；
2. 上传一段干声（建议 ≤5 分钟，采样率不限，内部走 ffmpeg 解码）；
3. 调参数 → 开始变声 → 任务面板看进度 → 原声 / 变声 A·B 对比。

### 训练一个新音色（LoRA）

1. 准备 10~30 分钟**干净干声**（无伴奏、无混响、单人）放进一个目录；
2. 「音色工坊 → LoRA 微调」：选底模、填语料目录、设轮数与 rank → 开始；
3. 流水线自动完成：预处理切分 → 提 F0 → 提内容特征 → 生成训练清单 → 微调 → 建索引；
4. 完成后模型库里出现 `<名字>.pth`（底模+适配器已折入）与 `<名字>.lora.pt`（适配器）。

## 参数说明

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 变调（f0_up_key） | 0 | 男转女常用 +12，女转男 -12 |
| F0 方法 | rmvpe | pm/harvest 为 CPU 方案；crepe 质量好但慢 |
| 检索占比（index_rate） | 0.3 | 模型没有 .index 时自动按 0 处理 |
| 清辅音保护（protect） | 0.33 | 防止清辅音发破，过大会咬字含糊 |
| 滤波半径（filter_radius） | 3 | harvest 的 F0 中值滤波窗口 |

## 注意事项

- RVC 的 `assets/hubert/hubert_base.pt` 是硬编码相对路径，因此**推理期间会临时
  把工作目录切到 `vendor/rvc`**，调用完立即还原（多个上游都依赖 cwd，不能常驻）；
- 读取音频走 ffmpeg 子进程，服务会自动把整合包 `runtime/` 加入 PATH；
- v2 只有 32k / 48k 配置（本分支没有 v2/40k.json），训练默认 32k；
- 权重落在 `vendor/rvc/assets/`（上游已 gitignore），模型库在 `trainer/.data/vc/models/`；
- 克隆他人声音需获得明确授权。

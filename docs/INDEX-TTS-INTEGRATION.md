# IndexTTS 接入方案（本地化 + 资源管控）

> 状态：**方案阶段，未开工**。本文只做论证与计划，代码一律未动。
> 上游：<https://github.com/index-tts/index-tts>（bilibili IndexTeam）
>
> 与 `NETEASE-INTEGRATION.md` 的关系：那份是**已落地**的网易模块方案；这份是**待决策**的第二套本地 TTS。
> 两者共用同一套接入模式（独立运行时 + 网关透传 + 资源管控），不要另起炉灶。

## 1. 它是什么，值不值得接

### 1.1 一手事实（2026-10 取自官方 README / 仓库）

| 项 | IndexTTS-2.5 |
| --- | --- |
| 参数量 | **0.8B**（比网易 Confucius4-TTS 的 1.3B 小） |
| 语种 | **中 / 英 / 日 / 西 / 阿**（5 种，少于网易的 14 种） |
| 克隆 | 零样本，单段参考音频 |
| 可控性 | **情感控制**（参考音频 / 8 维情感向量 / 文本描述）、**语速**（`duration_factor` 0.5~2.0）、**发音**（拼音 / CMU 音素 / 日文假名） |
| 精度 | **BF16**（2.5）或 FP16（2.0），官方称显存占用更低、质量损失极小 |
| 速度 | 官方 RTF（RTX 4090，`kv_cache=True`）：2.5 bf16 **0.2065**、2.5 fp32 0.2060、2.0 fp16 0.3257 |
| 安装 | **必须用 `uv`**（`uv sync --all-extras`），CUDA Toolkit ≥ **12.8** |
| 权重 | `hf download IndexTeam/IndexTTS-2.5` 或 `modelscope download`（国内可走 ModelScope） |
| 生产部署 | 官方提供 vLLM recipe |
| 许可 | **bilibili 模型使用协议**（不是 Apache），商用需自行确认 |

### 1.2 与现有三套模型的关系

| 模型 | 定位 | 语种 | 参数 | 本机实测/官方 RTF |
| --- | --- | --- | --- | --- |
| **网易 Confucius4-TTS** | **主服务**：免转写克隆、跨语种 | 14 | 1.3B | 本机 RTF **2.0~2.5**（4060 Laptop，beams=3） |
| **IndexTTS-2.5（拟接入）** | **补充**：情感/发音/语速精细可控 | 5 | 0.8B | 官方 0.2065（4090）；本机需实测 |
| GPT-SoVITS | 辅助：训练链 + 批量 | 中英日韩粤 | ~0.9B | 最快（已有链路） |
| MiMo 云端 | 免部署 | 中英 | — | 云端 |

**接入的理由（能力互补，不是性能替代）**：

1. **可控性**是它的独有价值——网易和 GPT-SoVITS 都没有「8 维情感向量 / 拼音注音 / 语速倍率」这套东西。
   做有声书、角色台词、需要指定多音字（`银<行|XING2>`）的场景，它是目前唯一能精确控制的本地方案。
2. **更小更快**：0.8B + BF16，显存压力比网易小（预估常驻 2~3 GB vs 网易 4.9 GB），
   8 GB 卡上余量更足。
3. **代价**：只有 5 语种，跨语种能力弱于网易——所以它**不能替代主服务**，只能并列。

> 结论：接，但**定位为「精细可控的补充音源」**，导航上不抢主服务的位置
> （参见 `HANDOFF.md` 决策表中「网易为主服务」那条）。

## 2. 部署形态（沿用已验证的模式）

沿用网易模块验证过的三件套，**不发明新架构**：

```
浏览器 (5173) → 网关 (8787, /api/indextts/*) → IndexTTS 服务 (:9883, 独立 venv)
```

| 决策 | 取法 | 理由 |
| --- | --- | --- |
| 独立运行时 | `indextts/` 目录 + 独立 venv（用 `uv` 管） | IndexTTS 要求 CUDA ≥ 12.8、`uv` 环境，与 trainer(py3.9) / netease(py3.12) 都不适合混装 |
| 网关**无 supervisor** | 只做探活与透明转发 | 与网易一致：进程生命周期交给 `npm run dev:indextts`，`tsx watch` 重启网关时不误伤 |
| 独立端口 | `9883` | 9881=GPT-SoVITS、9882=网易、9883=IndexTTS |
| opt-in 启动 | `npm run dev:indextts`，并加 `netease.mjs` 同款的 `--skip-if-missing` | 没装权重 / 没建环境时不拖崩 dev 链路 |

**依赖注意（Windows 特定）**：
- `--all-extras` 里的 **DeepSpeed 在 Windows 上难装** —— 按官方提示去掉，只留 `--extra webui`（我们不需要 webui，可全不要）
- CUDA Toolkit **12.8+** 是硬要求（本机驱动 572.61 → CUDA 12.8 ✓，但需确认系统装了 Toolkit 而非只有驱动）

## 3. 资源管控（本次需求的重点）

用户明确要求：**和网易一样要有显存控制 / 内存控制 / 检测等性能管控**。
现有底座已成型，接入时只需**扩展数据**，不需要重写机制。

### 3.1 复用现有四个组件

| 组件 | 位置 | IndexTTS 接入要做什么 |
| --- | --- | --- |
| **资源预估卡** `ResourceBudget` | `app/src/components/features/ResourceBudget.tsx` | 成本表 `lib/resources.ts` 增加 `'indextts'` 项：显存 ~2.5 GB（BF16，实测后校准）、内存 ~2 GB |
| **显存/内存读数** | 网关 `/api/health` 的 `host`（Node `os.freemem`）+ 服务侧 nvidia-smi 口径 | IndexTTS 服务照抄 `netease/app/hardware.py` 的 **nvidia-smi 优先 → 退回 torch** 取数（见 HANDOFF 坑 17，torch 只看本进程，会误判） |
| **跨服务仲裁** `arbiter` | `server/src/services/arbiter.ts` | `FocusEngine` 增加 `'indextts'`；`RELEASE_ENDPOINTS` 增加 `indextts: ['/v1/unload']`，让「只跑一个模型」覆盖三套服务 |
| **体检脚本** | `scripts/preflight_netease.py` 模式 | 新增 `preflight_indextts.py`：解释器 / torch / CUDA 12.8 / 依赖 / 权重 / 端口；同样的 `--allow-missing` 语义 |

### 3.2 门禁数值（先给估计值，实测后回填）

| 项 | 估计值 | 说明 |
| --- | --- | --- |
| 显存门槛（准入） | **3072 MB** | 0.8B BF16 约 1.6 GB 权重 + 激活值与 KV cache；给 3 GB 留余量。实测后校准 |
| 常驻占用 | ~2.5 GB | 显著低于网易的 4.9 GB，是它在本机的主要优势 |
| 内存 | ~2 GB | 权重加载期 RSS；粗估，实测校准 |
| 与网易互斥 | **必须** | 2.5 + 4.9 = 7.4 GB，8 GB 卡上并存必然抖动；走 `focus()` 仲裁，不共存 |

### 3.3 界面上要给出的三件事（与网易一致）

1. **跑之前先给数字**：「需要 X GB · 空闲 Y GB / 共 Z GB」+ 内存；
2. **不够时给可执行动作**：`只跑这一个模型`（focus）/ `释放常驻显存` / `关闭 GPT-SoVITS`；
3. **拿不到读数就说未知**，不编乐观结论。

## 4. 分阶段计划

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 0 | 环境核实：CUDA Toolkit 版本、`uv` 可用性、磁盘余量 | ⬜ 待做 |
| 1 | 拉仓库 → `uv sync`（去 DeepSpeed）→ 下 IndexTTS-2.5 权重（ModelScope 优先） | ⬜ 待做 |
| 2 | `indextts/` 服务骨架：FastAPI + `/health`（含 nvidia-smi 显存口径）+ `/v1/synth` + `/v1/unload` | ⬜ 待做 |
| 3 | 网关透传 `/api/indextts/*` + health 汇总（含 `enabled` 态） | ⬜ 待做 |
| 4 | 前端页面 + 导航分组（标注「IndexTTS-2.5 · 情感可控」，与网易分开成组） | ⬜ 待做 |
| 5 | **资源管控接入**：成本表 + 仲裁引擎项 + 体检脚本 + 预估卡 | ⬜ 待做（本次需求核心） |
| 6 | 实测：显存常驻、RTF、情感/发音/语速三项可控性验证，回填 §1、§3.2 的估计值 | ⬜ 待做 |
| 7 | 可选：vLLM 生产部署（需要 Linux/WSL2） | ⬜ 后续 |

**每个阶段独立可验证**：阶段 5 的验收 = 在 IndexTTS 页面看到预估数字 + 显存不足时能一键让出资源。

## 5. 风险登记

| 风险 | 概率 | 影响 | 处置 |
| --- | --- | --- | --- |
| **许可不是 Apache** | 高 | 商用受限 | 官方为 bilibili 模型使用协议；商用前必须单独确认，界面上标注来源（沿用 `SourceNote` 的做法） |
| 依赖 `uv` 且 CUDA ≥ 12.8 | 中 | 装不上 | 阶段 0 先核实；CUDA Toolkit 缺失就先装 Toolkit（本机驱动已满足） |
| DeepSpeed 在 Windows 难装 | 高 | 安装失败 | 按官方提示去掉该 extra；它只是「可能加速」，非必需 |
| 与网易/GT-SoVITS 抢显存 | 高 | 抖动或 OOM | 走已落地的 `arbiter.focus()`，三套服务互斥，不共存 |
| 语种只有 5 种 | 高 | 覆盖范围小于网易 | 明确为「补充」而非「主服务」，导航不抢位 |
| RTF 预估失准（4090 数据外推到 4060 Laptop） | 中 | 期望落差 | 阶段 6 实测后回填，不在方案里写死承诺 |
| 上游迭代快 | 中 | 接入面漂移 | 接入面收窄到一个薄适配文件（照抄 `tts_engine.py` 的做法） |

## 6. 与「是否已决定」的说明

本文**不是开工许可**。按 `HANDOFF.md` 的流程，落地前需要用户确认：

1. 是否接受「IndexTTS 为补充、网易仍为主服务」这一定位；
2. 是否接受 ~5~8 GB 额外磁盘（权重 + `uv` 环境）；
3. 商用场景是否需要先走许可确认。
